# Changelog

All notable changes to this project are listed here. The format follows [Keep a Changelog](https://keepachangelog.com/en/1.1.0/), and versions follow [Semantic Versioning](https://semver.org/spec/v2.0.0.html).

## [1.6.0] - 2026-11-17

1.6.0 makes the native orchestrator the main toolkit: `npm start` now opens it, and the frozen SDK pipeline moved to `npm run sdk`. It refuses workflows the model writes on the spot (Claude Code's `ultracode` keyword), makes `ORCH_BUDGET_TOKENS` cap a whole `npm run auto` run, keeps MCP servers and account connectors out of every SDK role by default, and hooks and the session-title call out of the triage, and moves to Claude Code 2.1.326 and Agent SDK 0.3.326. What 2.1.326 changed for this repo, and what was checked, is in [docs/claude-code-updates.md](docs/claude-code-updates.md), "What happened on 2026-11-17"; the live probes are in [docs/data/live-checks-2026-11-17.md](docs/data/live-checks-2026-11-17.md). Upgrading: update Claude Code to 2.1.326, then run `npm install` and `npm run claude-update` in a checkout; change every `npm start -- --repo ...` to `npm run sdk -- --repo ...`; set `ORCH_BUDGET_TOKENS` for the whole run. The plugin gains one setting, `workflow_guard` (21 in all), and the workflow guard hook.

The seven items 1.5.1 listed as known: the other SDK roles' MCP servers and connectors, fixed (`src/agent.test.ts`); the per-session cap, fixed (`src/verify.test.ts`, "auto.sh run-wide cap", and `src/run-budget.test.mjs`); the triage's hooks, fixed (`src/agent.test.ts`; live-checks-2026-11-17.md, Check 1, for the project's hooks); the small haiku call, fixed (`src/agent.test.ts`; Check 2); `strictMcpConfig` alone, still listed, with what Check 3 showed; a triage stopped by the cap, established live (Check 4), with two limits still listed; the old `AUTO` benchmark numbers, now marked (`bench/analyze.test.mjs`). Each is below.

Checked, nothing changed: Claude Code 2.1.326 warns at startup about an `--allowedTools` or `--disallowedTools` entry that does not look like a complete rule. The warning prints on stderr in text mode and not with `--output-format stream-json`, which `scripts/orchestrate.sh` uses. Run in text mode with an unknown model name (no model call), the launcher's full lists draw no such warning (a broken entry such as `--disallowedTools "Bash(git"` does). If you set your own list with `ORCH_ALLOWED_TOOLS`, check it the same way: `claude -p hi --model no-such-model --allowedTools <your rules> 2>&1 | head`.

### Changed

- **`npm start` now starts the native orchestrator, the main toolkit; the SDK pipeline moved to `npm run sdk`** (`package.json`, `src/cli.ts` usage and resume texts, `CLAUDE.md`, `README.md`, `docs/`). `npm start` runs the same command as `npm run orchestrate` (`claude --agent orchestrator --plugin-dir dist/dashboard`, an interactive session). The SDK pipeline, still frozen, is `npm run sdk -- --repo <dir> --task "..."`; its flags are unchanged. `package.json` gains a `description` that names native as the main toolkit, and lists the native scripts first. `src/policy.test.ts` holds the rule. What to do: change scripts, CI jobs and habits that called `npm start -- --repo ...` for the SDK pipeline to `npm run sdk -- --repo ...`; a script that runs `npm start` unattended would now open an interactive session and wait.
- **Agent SDK 0.3.326** (`package.json`, `package-lock.json`). The SDK pipeline now runs the Claude Code 2.1.326 that this SDK carries. What to do: `npm install` in a checkout; `npm run claude-update` then prints `ok sdk` instead of a `note sdk` line.
- **`ORCH_BUDGET_TOKENS` caps the whole `npm run auto` run, not each session** (`scripts/auto.sh`, new `scripts/run-budget.mjs`, `src/triage.ts`, `src/agent.ts`, `src/retry.ts`). The triage call gets the cap as before; before each later session (the plain session, the reviewer, the orchestrator, an escalated orchestrator) `auto.sh` subtracts what the run has spent so far and gives the session only the rest. What a call spent is the cost it reports (the triage decision's new `costUsd`, a session's `total_cost_usd`), at 1M tokens per dollar, the rate the launcher already uses; without a cost, its token count. With less than 10k left, the smallest cap the scripts accept, no session starts: the run prints `budget: ORCH_BUDGET_TOKENS=<cap> is the cap for the whole run ...` and exits 3. A triage call the cap stopped has spent the whole cap, so no session follows it (1.5.1 started the orchestrator with the full cap again): the run prints `budget: the triage call reached ORCH_BUDGET_TOKENS=<cap> ...` and exits 3, and its decision carries `capStopped: true`. `npm run native` is one session and keeps its cap as it is; the SDK CLI's `--budget` is unchanged. What to do: set the cap for the whole run, about the sum of what you set per session before; a script that runs `npm run auto` may treat exit code 3 as "cap spent, raise `ORCH_BUDGET_TOKENS`".
- **New switch `ORCH_SDK_MCP`** (`src/agent.ts`; SDK pipeline only). By default no SDK role takes an MCP server (below, under Fixed). `ORCH_SDK_MCP=project` gives the writer, the verifier and solo the servers of the `.mcp.json` in their folder (the worktree root), passed as written and without Claude Code's approval step for a project's `.mcp.json`; the planner, the explorer and the triager never get one, and no role takes an account connector. What to do: set it only if your SDK workers need the project's own MCP servers, and only for a project whose `.mcp.json` you trust.
- **Workflows the model writes on the spot are refused; the saved `orchestrate` workflow still starts** (new `.claude/hooks/workflow-guard.mjs`, PreToolUse on `Workflow`, in `.claude/settings.json` and the plugin's `hooks.json`). Claude Code's `ultracode` keyword, or a plain request for a workflow, made the model write a workflow script and run it with Claude Code's own agents, outside the plan check, the run journal and the review rules. The guard refuses every Workflow launch with exit 2 except `{"name": "orchestrate"}` or `{"name": "orchestration:orchestrate"}` (with optional `args`) whose saved file is there; a script, a script path, any other name and any input shape it does not know are refused (reasons `inline_script`, `script_path`, `name_not_allowed`, `workflow_file_missing`, `unknown_shape`). Deny-only; one record per decision in the new `workflow-guard.jsonl`. Claude Code's own `disableWorkflows` would have removed the saved workflow too. Tested in `src/workflow-guard.test.mjs`; probed live (docs/data/live-checks-2026-11-17.md, Check 5): an ad-hoc launch arrives as `{"script": ...}` and was refused before it ran, the saved `orchestrate` and `orchestration:orchestrate` toy workflows passed. What to do: start orchestrated work with the orchestrator or `/orchestrate` (`/orchestration:orchestrate` with the plugin); to let every workflow run again, set `ORCH_WORKFLOW_GUARD=off` or the new plugin setting `workflow_guard` to `off` (the 21st setting, in `/config`).
- **The nudge answers the `ultracode` keyword** (`.claude/hooks/nudge.mjs`, now also at UserPromptSubmit, in the project and the plugin). A typed prompt that holds the word `ultracode` gets one line of context: keyword-started workflows are off in this project and the task goes through the orchestrator. UserPromptSubmit also fires for a subagent's report, a task notification and another session's message, and its input carries no field that says which (read from the 2.1.326 binary), so the hook tells them apart by how their text opens (`typedPrompt` in `.claude/hooks/state.mjs`: a report opens with `Another Claude session sent a message:` and `<agent-message`, as recorded in a live session where the first version fired on one); they get nothing. Other prompts get nothing; it never blocks a prompt, and `ORCH_NO_NUDGE` does not silence it. Tested in `src/workflow-guard.test.mjs`. What to do: nothing.
- **`bench/analyze.mjs` marks triage tokens counted before 1.5.1** (`bench/analyze.mjs`, `bench/report.mjs`; 1.5.1 listed this as known). A run whose campaign manifest has a `plugin_version` below 1.5.1, or none, and whose logged routes carry tokens gets `triage_pre_fix: true`; `summary.json` gets a footnote in `notes`, which `analyze.mjs` prints and the report lists under Caveats. The token counts are left as logged. Tested in `bench/analyze.test.mjs`; no benchmark was run. What to do: read `AUTO` numbers of a marked campaign as counting the old, larger triage call, and run a new campaign to compare on the current one (bench/README.md).

### Fixed

- **The SDK roles other than the triager took MCP servers and claude.ai account connectors** (`src/agent.ts`, `leanOptions`; 1.5.1 listed this as known). Every role (planner, explorer, writer, verifier, solo, triager) now passes `disableClaudeAiConnectors: true` in its flag settings and `strictMcpConfig: true` with `mcpServers: {}`, unless `ORCH_SDK_MCP=project` (above). `persistSession: false` and `maxBudgetUsd` stay triage-only. `src/agent.test.ts` checks every role's options with a faked model; no live run of a worker was made. What to do: nothing, unless a writer, verifier or solo relied on an MCP server: then set `ORCH_SDK_MCP=project` with the server in the project's `.mcp.json`.
- **The token cap counted per session** (`scripts/auto.sh`; 1.5.1 listed this as known). See Changed. `src/verify.test.ts` ("auto.sh run-wide cap") runs `auto.sh` with a faked triage and a faked `claude` and checks the cap each session gets, and `src/run-budget.test.mjs` the arithmetic. What to do: see Changed.
- **The triage session ran the hooks of the project it reads** (`src/agent.ts`; 1.5.1 listed this as known). The triager now passes `disableAllHooks: true` in its flag settings, which rank above the project's: no hook of the project's settings runs in it (the setting turns off every hook, a plugin's too, but that part was not probed), and no status line command (a headless call shows none). Hooks of managed settings still run. It keeps `settingSources: ["project"]` and `agent: ""`, so it still reads the project's settings and CLAUDE.md. Checked in `src/agent.test.ts` with a faked model, and live in [docs/data/live-checks-2026-11-17.md](docs/data/live-checks-2026-11-17.md), Check 1: a triage of a folder whose settings register hooks ran none of them and left no record in the folder's `.claude/state`, while a control run without `disableAllHooks` ran three and left the review-gate record. Plugin hooks were not exercised: the triage reads project settings only, so it loaded no user-enabled plugin in either run. What to do: nothing.
- **The triage call made a small haiku call to name its session** (`src/agent.ts`, `TRIAGE_TITLE`; 1.5.1 listed it as known). The haiku call of about 1,650 tokens in every recorded triage is Claude Code's session-title call (its debug log says `source=generate_session_title`). The triager now passes the SDK's `title` option (`"triage"`), which the SDK documents as skipping automatic title generation; live, the call was gone from `modelUsage` and from the debug log (live-checks-2026-11-17.md, Check 2), and `src/agent.test.ts` checks the option. The triage writes no transcript by default, so the title shows nowhere; with `ORCH_SESSION_PERSISTENCE=1` its kept transcript is titled "triage". The other roles still make the call, about 0.0002 USD per session. What to do: nothing.
- **The native judge's prompt capture took a subagent's report for a typed request** (`.claude/hooks/prompt-capture.mjs`, `.claude/hooks/state.mjs`). With `ORCH_JUDGE=native`, `prompt-capture.mjs` keeps what the person typed as the judge's only authority. A subagent's report reaches the session as a UserPromptSubmit whose text opens with `Another Claude session sent a message:` before the `<agent-message>` tag, so the old check, which looked for the tag at the start, recorded it as a request. Both hooks now share `typedPrompt`, which also knows that opening and the `source: "poll_event"` field. Tested in `src/judge-hook.test.mjs` (prompt capture). What to do: nothing.
- **`mcpServers` went on Claude Code's command line, which Agent SDK 0.3.326 deprecates** (`src/agent.ts`, `src/judge.ts`). Every `query()` of the SDK roles and of the Bash judge passes `mcpServersDelivery: "initialize"`, so the servers reach Claude Code over stdin and a server's `env` and `headers` stay off the command line. The SDK says the Claude Code it carries, which this repo runs, takes it. What to do: nothing.
- **`npm run check-plugin` failed, and git listed an untracked file, after Claude Code loaded the pane from `dist/dashboard`** (`scripts/build-plugin.mjs`, `.gitignore`). Loading a mod from a folder (`npm start`, `npm run orchestrate`) makes Claude Code 2.1.326 write `tsconfig.json` at that folder's root and its type files under `.claude-plugin/types/`; the build writes neither. The check now skips exactly those two paths at the root of `dist/dashboard`, and git ignores the `tsconfig.json` (the types folder brings its own `.gitignore`). Any other extra, missing or changed file in `dist/` still fails the check; `src/build-plugin.test.mjs` covers both. What to do: nothing; the generated files may stay.

### Known and not fixed

- Claude Code 2.1.326 lets sandboxed commands write to fewer home folders and allows some of them back only through `sandbox.filesystem.allowWrite` in user or managed settings. Skill drafts live under `~/.claude/orchestration/skill-drafts/`, outside the project. Whether a sandboxed implementer can still write there was not established: the probe could not start a sandbox on the test machine (`socat` missing). What to do if you run implementers in the sandbox: try a `KIND: skill` slice once, and if its writes are refused, add that folder to `sandbox.filesystem.allowWrite` in your user settings.
- `claude plugin list` on 2.1.326 prints `Note: subagentStatusLine is deprecated in favor of mods and will stop working in a future release.` for the setting the plugin's `settings.json` holds (the worker rows under the prompt). The docs name no mod interface for those rows, so there is nothing documented to move to; Claude Code's changelog even says at 2.1.323 that the setting was removed, yet the 2.1.326 binary still runs it. Nothing was moved. What to do: nothing; when it stops, the worker rows take Claude Code's default look and no gate is affected.
- Telling a typed prompt from other UserPromptSubmit input rests on how the text opens (`typedPrompt`, Changed and Fixed). Claude Code documents no field for it, so a new kind of message, or a changed opening, would count as typed until the hook learns it; a person who types such an opening is taken for a message.
- The 1.6.0 fixes to the SDK roles' options were probed live for the triager only (live-checks-2026-11-17.md, Checks 1 to 3: no hook, no MCP tool, no title call, with `mcpServersDelivery: "initialize"` passed); the other roles (planner, explorer, writer, verifier, solo) were checked with a faked model only. Whether `ORCH_SDK_MCP=project` servers start in a worker, and whether `${VAR}` in a `.mcp.json` is expanded when passed this way, was not probed.
- The Bash judge's own call (`askOpus` in `src/judge.ts`) passes no `disableClaudeAiConnectors`; whether its session takes account connectors with `settingSources: []` and `strictMcpConfig` was not established.
- The run-wide cap of `npm run auto` counts a session that printed no readable result (a crash with no output) as having spent nothing, since nothing reports what it spent.
- `strictMcpConfig` alone (1.5.1, Known and not fixed): in one live triage without `disableClaudeAiConnectors`, no connector tool reached the session or its request, but Claude Code still fetched the account's connector list (live-checks-2026-11-17.md, Check 3). A longer session, in which a connector might connect later, was not probed, so every role keeps passing both options.
- A triage stopped by the cap (1.5.1: tests only) is now established live (live-checks-2026-11-17.md, Check 4): it ends as `error_max_budget_usd` with `capStopped: true`, and `npm run auto` exits 3 with no session. The same check shows two limits that stay: Claude Code checks the cap after each request, so one request can overshoot it (0.051 and 0.070 USD against a 0.01 USD cap, on a cold cache), and a triage on a warm cache (about 0.003 to 0.004 USD on sonnet) is never stopped by the smallest cap, 10k. What to do: treat `ORCH_BUDGET_TOKENS` as a stop after the request that crosses it, not a hard ceiling.
- The workflow guard (Changed) refuses the Workflow launch only. Claude Code still highlights the `ultracode` keyword and the prompt still reaches the model, which may then do the task another way: in probe (b) of Check 5 it fell back to launching subagents itself, which the plan check blocks only while a run is open and this repo's `permissions.deny` blocks only where it is copied. A session that loads neither this project's `.claude/settings.json` nor the plugin, or turns hooks off, is not guarded. The guard trusts the name: a file a model writes at `.claude/workflows/orchestrate.js`, or another project's own `orchestrate` workflow where the plugin is on, passes as the saved workflow; the project copy cannot see where the plugin is installed, so it lets `orchestration:orchestrate` through unchecked. Resuming a stopped run by `scriptPath` is refused: start the saved workflow again. `scriptPath` and `resumeFromRunId` were read from the tool's schema text in the binary, not probed. What to do: keep `.claude/workflows/` under review like code, and copy the `permissions.deny` rules into projects where the plugin runs.
- On 2.1.326, seven of the headless allow rules (`git -C * branch --show-current`, `worktree list`, `worktree add`, `add`, `commit`, `merge`, `reset --merge`) draw a startup warning that the `*` before the rest of the command also matches options inserted there. This is the known width of the `git -C *` rules (`scripts/orchestrate.sh` says so); they were not changed.

## [1.5.1] - 2026-11-16

1.5.1 fixes the triage call: the one read-only model call that picks a route for `npm run auto`, `npm run route`, the `/route` skill and the SDK pipeline (`npm start`). It carried the MCP tools of the person's claude.ai account connectors, which it can never use, the token cap did not reach it, and it wrote a session transcript. Measured once, on one machine, the same triage used 14,030 tokens instead of 437,331, about 0.03 instead of 0.69 USD, with the same route and the same facts ([docs/data/live-checks-2026-11-16.md](docs/data/live-checks-2026-11-16.md), Check 10). Upgrading: no plugin setting and no hook changed; the plugin changes only in its version. The `/route` skill runs `npm run route` in a checkout of this repo (`$ORCH_HOME`, by default `~/claude-code-orchestration`), so it gets the fix only when that checkout is updated. `ORCH_BUDGET_TOKENS` now also caps the triage call of `npm run auto`, and a triage that reaches the cap sends the task to the orchestrate route (below, under Changed).

### Changed

- **`ORCH_BUDGET_TOKENS` also caps the triage call** (`scripts/auto.sh`, `src/route.ts`, `src/triage.ts`). `scripts/auto.sh` passes the cap to `src/route.ts` as `--budget`, and the triage call gets it as the SDK's `maxBudgetUsd`, at 1,000,000 tokens per dollar, the rate the launcher uses for its sessions. The cap applies to each session on its own: first the triage call, then each session the route starts. A run can therefore spend more than the cap in total. A triage stopped by the cap is not retried. It takes the fallback of a failed triage, the orchestrate route, and its logged reason says `the token cap stopped it, error_max_budget_usd`; that orchestrate session gets the same cap again. What to do: keep the cap well above what a triage costs, or force a route with `ORCH_MODE` to skip triage. The cap is spent in dollars, not in tokens used, and a dollar of real use is between about 0.2M and 1.8M tokens, depending on the mix of cache and output tokens. The recorded triage used 14,030 tokens but cost about 0.029 USD, so it took about 29k tokens of the cap; a cap of 20k would have stopped it.
- **`npm run route` takes `--budget`** (`src/route.ts`). `npm run route -- --repo <folder> --task "..." --budget 300k` caps the triage call with a token count of at least 10k. A bad value prints the usage message and exits 2 before any model call. What to do: nothing; without the flag the call has no cap, as before. The `/route` skill passes none.

### Fixed

- **The triage call carried MCP tools it can never use** (`src/agent.ts`, `triageOptions`). It loaded the MCP tools of the person's claude.ai account connectors: 144 in the recorded run (Notion, Google Drive, Claude Docs and Canva), 99 in the tool list of every request and 45 more that arrived later. The triager reads with Read, Glob and Grep only, so it can use none of them. The call now passes `strictMcpConfig: true` and `mcpServers: {}`, and `disableClaudeAiConnectors: true` in its `settings`, so it takes no account connector and no MCP server, also none a project or a plugin names. In Check 10 its session had no MCP tool. Part of the measured cut is one request fewer, which was the model's choice, not the fix.
- **The token cap did not reach the triage call** (`scripts/auto.sh`, `src/route.ts`); 1.5.0 listed this as known. See Changed.
- **The triage call wrote a session transcript** (`src/agent.ts`). It writes none under `~/.claude/projects/` unless `ORCH_SESSION_PERSISTENCE=1`, the switch that also keeps the transcripts of the launcher's own sessions.

These fixes are in code the SDK pipeline shares, so its triage call also takes no MCP server or account connector and writes no transcript. Its `--budget` accounting is unchanged: triage tokens count as before, and its triage call gets no dollar cap.

### Known and not fixed

- The other SDK roles (planner, explorer, writer, verifier, solo) pass the options the triage call passed before this fix, so nothing keeps MCP servers or account connectors out of them. Their token use was not measured.
- The cap is per session, not per run (see Changed).
- The triage session still runs the project's hooks, as in Check 8.
- A small haiku call of about 1,700 tokens appears in both recorded runs (Checks 8 and 10); its source was not looked into.
- Whether `strictMcpConfig` alone keeps account connectors out was not established, so `disableClaudeAiConnectors` is passed as well.
- A triage stopped by the cap is covered by tests only; the live call used 0.03 of its 0.3 USD cap.
- Benchmark numbers of the `AUTO` arm published before 1.5.1 count the triage call as it ran before this fix (`bench/analyze.mjs` adds each logged route's tokens).

## [1.5.0] - 2026-11-16

1.5.0 carries the fixes of the audit of 2026-11-16: 79 findings, of which 65 are fixed, 2 fixed in part, 9 were wrong pages, 1 is kept as a stated limit and 2 were decided against. The full list, with the fix of each, is in [docs/research-2026-11-16.md](docs/research-2026-11-16.md); this entry names what a person notices. It also asks for shorter output to the person, keeps the test gate under Claude Code's subagent stall limit, and rewrites the documentation. Upgrading: no plugin setting changed. Plain sessions now use the Concise output style, `npm run native` and `npm run auto` print text to a terminal, the Bash judge and the headless git rules refuse more forms, and the native judge keeps its record of your requests in a new place (each below, under Changed). The changed hooks take effect in a new session.

### Changed

- **Short output to the person** (`.claude/agents/orchestrator.md`, `.claude/skills/route/SKILL.md`, `.claude/hooks/nudge.mjs`). The orchestrator's first line is `Path: light|full - <reason>` (the route skill: `Route: <mode> - <reason>`). The plan is shown once, one line per slice; the full plan with the constraint texts goes only into the PLAN REVIEW brief. Progress is one short line, only when something changed. The final report has at most 15 lines, one per slice with a pointer to its evidence (`<id>: pass|fail - <evidence pointer>`). What to do: ask for the full plan, the gaps or the logs when you want them; a requested answer keeps its length. `src/contracts.test.ts` checks the rule in all three texts.
- **Headless output in a terminal** (`scripts/run-result.mjs`, `scripts/orchestrate.sh`, `scripts/auto.sh`). When its output is a terminal, `npm run native` and `npm run auto` print the result text and one totals line (`turns 41, 723 s, exit 0`). Piped or captured they print the JSON document as before, so scripts that read it are not affected. What to do: pipe the output (`| cat`, `| jq`) when you want the JSON in a terminal.
- **Plain sessions use the Concise output style** (`scripts/orchestrate.sh`, `package.json`). A plain session started by the headless launchers (`ORCH_AGENT=none`, and the plain and reviewed routes of `npm run auto`) and `npm run plain` run in Claude Code's built-in Concise style. What to do: set `ORCH_OUTPUT_STYLE=default` (or empty) to keep Claude Code's default style in a headless run, or another style name to use that one; a value that is not a plain word stops the launch before any model call. For an interactive plain session in the default style, run `claude --settings '{"agent":""}'` instead of `npm run plain`.
- **The Bash judge refuses more forms, and passes three it refused** (`src/judge.ts`, `.claude/hooks/judge-core.mjs`, changed together). It now refuses: `<<` after an open `[` (`$[...]`, an array subscript); a brace expansion that holds a process substitution; git options whose value runs a shell (`grep -O`/`--open-files-in-pager`, `difftool -x`/`--extcmd`, `--upload-pack`, `--exec`, the `filter-branch` filters) when the value would be refused as a command of its own or is built at run time; the config keys `gpg.*.defaultKeyCommand`, `browser.*`/`man.*` `cmd` and `path`, `imap.tunnel`, `gc.recentObjectsHook` and `hook.<name>.command`; a here-document delimiter holding `$` or a backtick; `PS0`, `PS1`, `PS4`, `BASH_FUNC_*` and `ZDOTDIR` among the exec-env names, and `PS4` on a line with `set -x`; `hash -p`, `hash name=path` and `enable -f`; assignments to zsh's `functions`, `aliases` and `commands` tables, also through `set -A` and an assigning `${...}`; `$(` or a backtick inside a quoted subscript. In SDK workers, a recursive `rm` or a push or remote change while the shell's folder is outside the working folder is refused (`cd` back first), and `rm` targets are resolved from the shell's folder. It passes again `GIT_EDITOR=true` and `GIT_EDITOR=:`, `git -c core.editor=true` (or `:`), and `IFS=`, each only in that exact form: `EDITOR=true`, `+=`, a partly quoted value and `--config-env` stay refused. What to do about the new over-blocks: leave `PS4` at its default with `bash -x`; write a plain or quoted here-document delimiter (`<<'EOF'`); commit with `-F <file>` when the message holds a backtick inside `name[...]`; do not name a variable `commands`; read an exec key from the config file, not with `git config --get`; write a search for a table word (`grep functions= f`) as its own command, not behind `if` or `xargs`; split a read of a table followed by `=` (`[[ ${#functions} == 0 ]]`) into two commands. docs/bash-judge.md section 11 lists each with its way around.
- **The native judge's record of your requests moved** (`.claude/hooks/state.mjs`, `prompt-capture.mjs`, `judge-hook.mjs`; only with `ORCH_JUDGE=native`). The typed requests are kept in `<CLAUDE_CONFIG_DIR or ~/.claude>/orchestration/judge-prompts/<project key>/prompts.jsonl`, outside the project, so a worker can no longer append to its own authority there. A `prompts.jsonl` in the project's `.claude/state` is ignored. The test gate still runs the whole suite when an implementer stops, and the integrator runs it once more after the merge, so a brief never also asks a worker to run it: only the integrator's brief names it. A slice's reviewer runs the slice's own check, not the suite. The gated workflow's plan has an optional field `suite` (the command that runs the whole suite: one line of at most 300 characters, otherwise dropped and logged); the integrator brief gets "Then run the project's whole test suite once: <suite>", and without it the brief is as before. The researcher's instructions now say that `2>/dev/null` and `2>&1` are allowed, as the guard has allowed since 1.4.2.
- **`npm run check` runs its steps side by side** (`scripts/check.mjs`). Typecheck, the tests, check-agents and check-plugin start at the same time. Each step's output is held back and printed whole under one header when the step ends (`=== <step>: pass, N s ===`, or `FAIL (exit <code>)`), so two steps never interleave, and the last line is `check passed: ...` or `check failed: <names> ...`. ### Fixed

- **A test file run on its own left its temp folders behind** (`src/test-tmp.mjs`). `npm test` removes its temp root since 1.4.2, but a file run directly (`npx tsx --test src/x.test.ts`, `node --test bench/y.test.mjs`) had no root. Every test file now imports `src/test-tmp.mjs` first. Outside `npm test` it makes a folder `orch-test-XXXXXX` under the temp dir, sets it as `TMPDIR`, `TMP` and `TEMP` for the process and its children, and removes it at exit, also after a failed test or on SIGINT, SIGTERM or SIGHUP. ## [1.4.1] - 2026-11-15

1.4.1 hardens the Bash judge and the researcher guard. Upgrading: no setting changed. A quoted word that starts with an exec-env name and `=` (`PATH=`, `GIT_SSH_COMMAND=`, ...) is now denied on a line that runs git, rm or a shell, as the unquoted word already was, even when it is only an argument such as `git log --grep 'PATH='`: run that search as its own command. For a researcher, an unquoted glob in an option is denied: write `rg -g '*.md' x`.

### Changed

- **The exec-env rule reads a word's static prefix, quoted or not** (`.claude/hooks/judge-core.mjs`, `src/judge.ts`, [docs/bash-judge.md](docs/bash-judge.md#25-the-exec-env-rule)). The static prefix is the text of a word's literal pieces joined, quoted or not, up to its first dynamic or glob piece. When it starts with an exec-env name (`PATH`, `PAGER`, `GIT_SSH_COMMAND`, `LD_PRELOAD`, ...) and `=` or the append form `+=`, the line has an exec-env assignment, wherever the word stands and whatever command precedes it. So `env "PATH=/x" git status`, `env PA"TH=/x" git status`, `export "GIT_SSH_COMMAND=sh -c id"; git fetch` and `PAGER+=evil git log` are denied on a line that runs git, rm or a shell, like the unquoted form was on 1.4.0. The judge no longer models where `env`'s or a launcher's own words end; a word is an assignment by its spelling alone. Out of reach, as before: a dynamic name part (`env ${P}ATH=/x git status`), `env -S` strings, and assignments never spelled `NAME=` (`read PATH`, `printf -v PATH`).
- **Cost of that rule (accepted).** Such a word is denied on a line that runs git, rm or a shell even when it is only an argument: `git log --grep 'PATH='`, `grep 'PATH=' f && git status`. The deny message says to run the search or echo as its own command. `grep -rn 'PATH=' src` alone still passes.

### Fixed

- **`find ... -rm` passed the judge.** `-rm` is bfs's name for `-delete`, and `find` with either is now denied (`judge-core.mjs`, `src/judge.ts`).
- **A long command could outlast the judge hook's timeout.** The judge's analysis was quadratic or exponential in the number of words: a command of 20,000 words took seconds (one form took about 27 s on 1.4.0) and a hook killed at its timeout does not block. The analysis no longer rescans earlier words for each word and stops at the first deny, and the same command now takes well under a second (about 0.15 s) (`judge-core.mjs`, `src/judge.ts`, tested in `src/judge-hook.test.mjs` and `src/judge.test.ts`).
- **The judge hook parsed every session's prompts.** `judge-hook.mjs` skips a line of `prompts.jsonl` that cannot hold this session's id before parsing it; the session check after parsing still decides.
- **The researcher guard missed a device path attached to an option and a glob in an option name** (`researcher-guard.mjs`). `grep --file=/dev/zero x` and `grep -f/dev/zero x` are denied like `grep x /dev/zero`; `/dev/null` stays allowed in each place. A glob in an option's name (`tail -?`, `rg -g*.md x`) is denied in any command, because the shell may expand it into another option, such as `-f` or `-delete`; the message says to quote the glob (`rg -g '*.md' x`) or use the long form (`--glob=*.md`). A glob in a long option's value (`--include=*.ts`) still passes.
- **Nothing proved the judge was never weaker than 1.4.0.** `src/judge-differential.test.mjs` runs the vendored 1.4.0 judge (`src/fixtures/judge-core-1.4.0.mjs`) against the current one over the judge tests, the corpus and generated forms: nothing 1.4.0 denies passes or is judged, nothing it judges passes, and a new deny comes only from the exec-env rule or `find -rm`.

### Changed

- **The orchestration pane is off until you turn it on** (`dashboard/register.tsx`, [docs/dashboard.md](docs/dashboard.md)). It is off at every session start in every terminal, herdr included; the herdr check is gone. `/orchestration on` turns it on and opens it focused, `/orchestration off` turns it off and closes it, `/orchestration` alone switches between the two, and the choice lasts for the session. While it is on, a typed prompt, an orchestration agent's start and a route verdict open it as before, and on a terminal narrower than 144 columns a toast says to type `/orchestration on`. While it is off nothing opens it, but the run is still recorded, so turning it on mid-run shows the run so far. The dashboard's hooks catch their own errors: a failing state write, `ui.open` or command registration never fails the prompt, agent start, tool call, turn or session start it wraps.
- **The test gate has a time budget** (`.claude/hooks/verify.sh`). A hook killed at its timeout (900 s) does not block, so the whole hook now ends within `ORCH_HOOK_BUDGET_S` (default 870). The test run gets `ORCH_TEST_TIMEOUT_S` (default 600) or the time left, whichever is less. The test baseline's base run and the bugfix check get only the time left: each base run gets the smaller of `ORCH_BASE_TIMEOUT_S` and its share of the time left less 10 s, and the helper is killed when the budget runs out. A bugfix check that has no time left or is killed blocks a `KIND: bugfix` slice with `bugfix_timeout`, counted with the other bugfix blocks. Both switches are read from the environment only; neither is a plugin setting.
- **A reviewer on opus or above gets up to 2 suggested skills** (was 1). The limit follows the launch's effective model: the call's `model`, else the agent file's. A sonnet reviewer, or a launch whose model cannot be ranked, keeps 1. Implementers and researchers keep 3. No model default changed.

### Fixed

- **A test suite that hung let the implementer finish.** The test gate ran the suite with no limit of its own, so a hanging suite ran until Claude Code killed the hook at its timeout, and a killed hook does not block. The suite now runs in its own process group and is killed with its children at the limit; the stop blocks as a test failure (`tests_failed`, with `timed_out` and `limit_s` in the gate record) under the same loop guard, and no base run follows. A suite that reads the terminal fails at once instead of stalling until the limit.
- **The review gate's loop guard missed block records without a timestamp.** It counted only earlier `block` records whose `ts` was at or after the last implementer's stop; a record with no `ts` now counts too (`review-gate.mjs`).
- **The gates parsed every session's log lines.** `readJsonl` in `run.mjs` takes a session id and skips another session's lines before parsing them, and `review-gate.mjs`, `handback-check.mjs` and `quote-check.mjs` read each log once per call; a record just written is read back from the end of the log only (`appendJsonl`).
- **Test-gate records had whole-second timestamps.** `verify.sh` now writes milliseconds, like the node hooks, so the run model orders a test-gate record against a stop in the same second.
- **The test gate misread event fields holding an escaped quote or backslash.** `verify.sh` reads `agent_type`, `agent_id`, `session_id` and `cwd` up to the closing quote, not the first escaped one, and undoes `\"`, `\\` and `\/`.
- **`npm run skill-publish` could push or merge commits the seal never covered.** It records the sealed branch's head, refuses to push when origin's `skill/<name>` holds commits that head does not, and `--merge` merges with `gh pr merge --match-head-commit <that head>`, so nothing pushed after the checks is merged (`scripts/skill-publish.mjs`).
- **A sealed skill file that git did not track passed.** The seal covers every file on disk, but an ignored or untracked file is never pushed. The skill gate and `npm run skill-publish` now fail when a file under `skills/<name>` is not committed on the branch, and a branch lookup that fails is a git-state failure in the gate (`skill-gate.mjs`).
- **The subagent status line parsed every session's launches.** `subagent-statusline.mjs` skips lines of other sessions before parsing and indexes the launches once per refresh.
- **`statusline/statusline.sh` could stall on git and showed no 7-day reset date on Linux.** It runs `git --no-optional-locks status` without untracked files (the count is of changed tracked files), kills a git that takes more than about a second and shows no count then, and kills git and removes its temp file when it is killed itself. Non-numeric values no longer break it, the 7-day window shows its reset date on Linux as well as macOS, and it reads its fields in one `jq` call.

## [1.3.0] - 2026-11-14

1.3.0 changes which model each role runs on, keeps Haiku out unless you allow it, and fixes the run log of headless runs. Upgrading: the plugin has one new setting, `allow_haiku` (empty by default), and no existing setting changed. Runs cost more than on 1.2.2, because the orchestrator and the implementer each moved up one model; one small two-part task measured $1.08 at list price against $0.81 before.

### Changed

- **Models: Fable plans, Opus does the tasks, Sonnet does the rest, and no Haiku.** The orchestrator (SDK planner) runs on Fable 5.2 (was Opus). The implementer (SDK writer) and the plain session (`npm run auto`'s plain route, the SDK's solo role) run on Opus (were Sonnet; the plain session used to run on whatever model Claude Code defaulted to). The researcher (SDK explorer) runs on Sonnet (was Haiku). The reviewer, integrator and triager stay on Sonnet, and the Bash judge and the escalated reviews stay on Opus. The third and last attempt of a slice is still a fresh implementer on Opus, which is now the same model as the first attempt. Cost per run goes up: the benchmark figures in the README were measured with the earlier models and the triage thresholds were set against a plain Sonnet session, and neither was measured again. `ORCH_MODEL_<ROLE>` and `ORCH_MODEL` still override each default.

### Added

- **The haiku rule.** `plan-check.mjs` raises a launch of any of this plugin's agents to sonnet when its model is in the haiku family (the call's `model`, else the agent file's `model:` line, so an agent file copied from an earlier version is covered). `ORCH_ALLOW_HAIKU=1` or the new plugin setting `allow_haiku` turns the rule off; `CLAUDE_CODE_SUBAGENT_MODEL` is left alone. Each raise goes to `model-floor.jsonl` in the state dir. The read router is unchanged: it only raises a model, so with a Sonnet researcher its haiku tier changes nothing.

### Fixed

- **The run log recorded the last wake-up of a headless run, not the run.** `claude -p` answers once per wake-up of the session: an orchestrator that launches agents stops, is woken by each agent's result and stops again, and every stop is a result with its own `num_turns` and `duration_ms`. `--output-format json` prints the last one only, so `runs.jsonl` logged a run of two minutes and three agents as `duration_ms: 8320` and `turns: 1`. `scripts/orchestrate.sh` now asks for the event stream (`--output-format stream-json --verbose`) and `scripts/run-result.mjs` reduces it to the document the script prints: the last result as before, plus `orch_totals` with `results` (how many results the session produced), `turns` (`num_turns` summed over them) and `wall_ms` (the run's wall time, measured by the script). `scripts/log-run.mjs` writes those two totals to `turns` and `duration_ms`. Tokens were already right: `modelUsage` in the last result covers the whole session. Rows logged before this fix keep their low figures. The bench's `num_turns` still comes from each document's own `num_turns`; its `N-UC` arm runs `claude` itself and keeps `--output-format json`.

## [1.2.2] - 2026-11-14

1.2.2 follows Claude Code 2.1.323 to 2.1.325. Claude Code updated itself and the update went around two things this repo relies on; both are fixed, and a script now checks for the same kind of change after every update.

### Fixed

- **`web-fetch`, a built-in subagent added in Claude Code 2.1.325, was not blocked.** The block list named six built-in types by hand in three places. The plan check took `web-fetch` for somebody's own agent, so a session with an open run could hand work to it and no gate saw that, and `permissions.deny` in this repo did not deny it. The names now live in one file, `.claude/hooks/builtin-agents.mjs`: the plan check reads it, `DENIED_AGENTS` in `src/config.ts` is built from it, and `policy.test.ts` keeps `permissions.deny` in step. Headless runs were not affected: `CLAUDE_AGENT_SDK_DISABLE_BUILTIN_AGENTS=1` still removes every built-in (checked on 2.1.325).
- **Claude Code's auto memory ran inside the judge and the SDK workers.** Each `claude -p` call of the native judge left an empty `~/.claude/projects/<temp folder>/memory` folder and carried the auto-memory instructions in its prompt; an SDK worker could write memory notes under its throwaway worktree's project folder. The judge hook, the SDK judge and every SDK worker now run with `CLAUDE_CODE_DISABLE_AUTO_MEMORY=1` (`workerEnv` in `src/judge.ts`).

### Added

- **`npm run claude-update` (`scripts/claude-update.mjs`).** Run it after Claude Code updates. It asks the installed Claude Code for its built-in subagent types (its start-up answer in safe mode; no model call) and fails when one is not on the block list; checks that the headless switches still leave no built-in agent, that the options `scripts/orchestrate.sh` and the native judge pass are still in `claude --help`, that the Agent SDK carries the same Claude Code as the installed one, that an installed plugin is current, and that `dist/` matches the sources. `--fix` repairs the machine: it writes newly found built-in types to `~/.claude/orchestration/builtin-agents.json`, which the plan check reads at once, and updates a stale plugin install. `--enable` installs and enables the plugin when it is off (`--fix` never turns it on: the plugin is opt-in). `--write-source` is for a maintainer: it adds the new types to `builtin-agents.mjs` and `permissions.deny` and rebuilds `dist/`. Details in [docs/claude-code-updates.md](docs/claude-code-updates.md).

### Changed

- Agent SDK 0.3.325 (it carries Claude Code 2.1.325; 0.3.322 carried 2.1.322, so the SDK pipeline ran an older Claude Code than the installed one). `@types/node` 26.6.6.

## [1.2.1] - 2026-11-10

### Fixed

- `npm run report` counted an agent once per stop record. An agent stops more than once (the test gate sends an implementer back, a resume, the stops around a hand-back) and each record carries its running total from the transcript, so the role table, and the cost table added in 1.2.0, counted such an agent's tokens two or three times: in the logs of 2026-11-01 to 11-03 implementer cache reads came out 72% to 76% too high. ## [1.2.0] - 2026-11-10

1.2.0 follows Claude Code 2.1.317 to 2.1.322 and closes three gaps found while researching it ([docs/research-2026-11-10.md](docs/research-2026-11-10.md), probes in [docs/data/live-checks-2026-11-10.md](docs/data/live-checks-2026-11-10.md)). It also carries the bug fixes from a read-only audit of the hooks, the SDK pipeline, the scripts and the dashboard, merged after 1.1.0; each of those has a test that failed before it. The brief and reply grammar, the gate reason names and the agent names are unchanged; one gate reason and one setting are new.

### Added

- Review gate: `implementer_unfinished`. A subagent that stops at its turn limit fires no SubagentStop (probed on Claude Code 2.1.322), so the test gate never ran for it and the journal counted no attempt: a turn-limited implementer could leave partial work that no gate saw, and with no other implementer the gate allowed with `no_implementer_in_session`. The gate now blocks while an implementer launched with the Agent tool has a SubagentStart and no later SubagentStop, until it is resumed and stops or a later implementer stop takes its slice over; two blocks, then `implementer_unfinished_gave_up` ([README, The gates](README.md#the-gates), [docs/brief-grammar.md, Gates](docs/brief-grammar.md#gates-slice-a1)).
- `handback-check.mjs` (PreToolUse on `SubagentHandback`, auto mode). A worker's report is read before it is delivered and sent back once when it has no `STATUS` line, or when a reviewer's pass leaves an id of its `CHECKS` line unanswered. `quote-check.mjs` runs on the same event, so an unverified quote is corrected before the orchestrator sees the report instead of after. Setting `handback_check` (`ORCH_HANDBACK_CHECK=off`), the 16th.
- Estimated cost in `npm run report`: cost by role and model at list prices (`scripts/prices.mjs`), the agents that started and never stopped, and cache rewrites. Telemetry records `tokens.cache_write_1h` and `cache_rewrites` (numbers only).
- A subagent status line shipped by the plugin (`subagent-statusline.mjs` through the plugin's `settings.json`): each worker's row shows its slice, attempt, model, tokens and progress.

### Changed

- The researcher's Bash list includes read-only search and paging: `grep`, `rg`, `find`, `head`, `tail` and `cat`, held by `researcher-guard.mjs` to forms that cannot write a file or start a program. On macOS and Linux Claude Code leaves the Grep and Glob tools out of an agent whose tools also name Bash, so a researcher launched from a plain session could not search at all: the logs since 2026-11-01 show 43 guard denials in about 26 researcher runs.
- A passing review on opus or a stronger model (`fable`) meets `opus_review_required`. The escalation still launches on opus by default.
- SDK pipeline (maintenance): Agent SDK 0.3.296 to 0.3.322, and the Bash judge's hook is registered with `onFailure: "block"`, so a guard that throws or returns nothing blocks the command.
- The orchestrator, the route skill and the nudge tell the session how to answer `implementer_unfinished` and never to accept a partial result as finished; the implementer waits for a command that was moved to the background before it reports.

### Fixed

- `npm run check-plugin` no longer fails after `npm run eval`: the eval writes its reports to `dist/plugin/evals/results` (ignored by git), which the comparison with a fresh build now leaves out.
- Hooks: a slice id that names an `Object.prototype` property (`constructor`, `__proto__`, `toString`) no longer throws in the run fold, and the Stop gate blocks instead of exiting 1 and letting the reply through when the run state cannot be read. `test-cmd.sh` detects `scripts.test`, not the word "test" anywhere in `package.json`.
- SDK pipeline: `waves()` breaks only real cycles and keeps a dependency that failed or is still pending, so a slice no longer runs without its dependency's work; a planner slice named `result` no longer collides with the integration branch; a bare 500/502/503/504 in error text is no longer retried as transient.
- Bash judge: `git config` keys that run programs (`difftool.*.cmd`, `mergetool.*.cmd`, `sendemail.*`, `web.browser`, `interactive.difffilter`, `init.templatedir`) are denied like the existing ones, in `src/judge.ts` and `.claude/hooks/judge-core.mjs`.
- Scripts: `scripts/auto.sh` resolves a relative repo path against the caller's folder (a missing folder is an error) and `scripts/report.mjs` reads legacy `runs.jsonl` rows without `subagents`.
- Workflow and UI: `maxRetries: 0` means no retries in the gated workflow; the status line prints a fallback when `jq` is missing; the dashboard progress step no longer shows a reviewer reply without a STATUS line as done (display only, run sign-off is unchanged).

### Known and not fixed

- The token budget restarts on `--resume` and is not applied to the plain and reviewed routes; the judge's own tokens are outside every budget.
- The bash judge does not read the shell string passed to `parallel`, `flock -c` or `script -c`, and still lets through `difftool.<n>.path`, `mergetool.<n>.path` and `browser.<n>.cmd`.
- The `/route` skill passes `$ARGUMENTS` inside double quotes, so a task containing quotes or `$(...)` is expanded by the shell.
- CI does not run or typecheck the dashboard.
- In the dashboard, the pipeline review cells and the phase state still read a reviewer reply without STATUS as done; `docs/dashboard.md` still says it shows as done.

## [1.1.0] - 2026-10-31

1.1.0 is the first stable release and the first tagged one. It is 0.4.0 plus the follow-ups listed under Fixed and Added. There was no 1.0.0 tag, and the versions before this one were not tagged.

### Fixed

- A slice is final only when its escalation rule is met: its latest review passed and it has no doubt signal, or a passing opus review came after its latest attempt. A run no longer closes on a sonnet pass that still needs an opus review, so that review and any further launch of the slice join the same run (ea62c55; [README, The gates](README.md#the-gates), [docs/brief-grammar.md, Run model](docs/brief-grammar.md#run-model)).

### Added

- `ORCH_SESSION_PERSISTENCE=1` keeps session and subagent transcripts in headless runs (`npm run native`, `npm run auto`, the bench), so telemetry records per-agent tokens, turns and models. Unset, headless runs behave as before (ec46ad9; [README, Telemetry and the read log](README.md#telemetry-and-the-read-log)).
- The `d3-reader` bench task (twelve questions over seven documents), the `reader-haiku`, `reader-sonnet` and `reader-routed` arms, and the route-040 benchmark of the read router (17fe23b, 69535bb). Results at n = 2 runs per arm, one task, direction only: the routed arm scored higher than the other two with fewer researcher tokens than `reader-sonnet`, but the model raise and the converted-text notes are confounded, and H14 is not called supported ([docs/benchmark-route-040.md](docs/benchmark-route-040.md)).
- A live probe of the `agent.spawn` mod hook for workflow agents: it runs under `claude -p`, fires for workflow agents and can rewrite their model and prompt. Routing workflow agents this way is feasible but not implemented (724d66f, 9ff6199; [docs/data/live-checks-workflow.md](docs/data/live-checks-workflow.md)).

### What 0.4.0 brought

Details in [README, What 0.4.0 adds to the gates](README.md#what-040-adds-to-the-gates) and [docs/research-2026-10-31.md, Implementation status](docs/research-2026-10-31.md#implementation-status-040).

- Brief and reply lines: `SOURCES:` and `READ:`, `KIND: bugfix`, `VALIDATE: gaps`, `SKILLS:`, `GAP: <0-100>` and `QUOTE:` ([Briefs and replies](README.md#briefs-and-replies)).
- Review precision: the gap cutoff (`ORCH_GAP_MIN`, default 80), validation of gaps before a retry, opus on the third attempt, and the native stall gate (`replan_required`).
- The test baseline (`inform` by default, `allow` opt-in) and the bugfix check for `KIND: bugfix` slices.
- Guards: the researcher Bash guard and the reviewer egress guard, both deny-only. The quote check for researcher `QUOTE:` lines. Plan and constraint re-injection after compaction (`compact-context.mjs`).
- The read router, opt-in (`ORCH_READ_ROUTER=on`) ([How a worker launch is shaped](README.md#how-a-worker-launch-is-shaped)).
- Skill suggestions in the plan check, on by default (`ORCH_SKILL_HINTS=off` to drop).
- Telemetry v2: tokens, turns, models and max-turn hits per agent, the file trail and the read log.
- 15 plugin settings as `userConfig`, bridged to the `ORCH_*` variables; an environment variable still wins ([Switches and plugin settings](README.md#switches-and-plugin-settings)).
- The gated workflow (shipped in 0.3.0) gained `gapMin`, `planCheck`, `planReview`, `refute` and `escalateLast`, all on by default ([The gated workflow](README.md#the-gated-workflow)).
- The native Bash judge hook is registered with `onFailure: "block"` and a 120 s timeout.

### Stability

In 1.x, these do not change incompatibly:

- The brief and reply line grammar ([docs/brief-grammar.md](docs/brief-grammar.md)).
- Gate reason names, such as `file_overlap`, `not_in_plan`, `replan_required` and `opus_review_required` ([README, The gates](README.md#the-gates)).
- The agent names (`researcher`, `implementer`, `reviewer`, `integrator`, `orchestrator`) and the `orchestration:` plugin namespace.
- The `userConfig` keys and the `ORCH_*` switches, with their defaults.
- The install path: marketplace `0xcvaliente/claude-code-orchestration`, plugin `orchestration`.

These stay opt-in or experimental and may change in a minor release:

- The read router (`ORCH_READ_ROUTER`); H14 is undecided.
- The native Bash judge hook (`ORCH_JUDGE=native`).
- The advisor (`ORCH_ADVISOR`).
- The eval suite (`npm run eval`), which has not been smoke-run.

Frozen: the SDK pipeline in `src/`, maintenance only since 0.3.0.

Known limitations are listed in [README, Known limitations](README.md#known-limitations).

### Upgrading

Installed plugin copies pick up the new version after a `/plugin` update or a reinstall, then `/reload-plugins`. No `userConfig` key or default changed after the 0.4.0 release commit (fc7360e), so there is nothing to migrate in settings. `ORCH_SESSION_PERSISTENCE` is a new environment variable for headless runs, not a `userConfig` key, and leaving it unset keeps the earlier behaviour. The one behaviour change is the finality rule above: a run waiting for a slice's opus review now stays open until that review runs or the run goes stale.
