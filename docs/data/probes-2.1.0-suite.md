Proposed changes outside this slice's files:
- `scripts/soak-gates.mjs:180`: with `--plant`, put the planted step first (or never cut a sequence before its planted step), so the planted test no longer depends on load.
- `statusline/statusline.sh:69-70`: a SIGTERM that arrives between `git ... &` and `STATUS_PID=$!` runs the EXIT trap while `STATUS_PID` is still empty, so git's process group is never killed. Seen in 2 of 8 side-by-side runs when the fake status killed its parent at once. Fix: in `git_cleanup`, also kill each remaining job's group (`for j in $(jobs -p); do kill -TERM -- "-$j"; done`), or ignore TERM, INT and HUP from just before the fork until both job ids are stored, then re-check for a signal that arrived in between.
- `.claude/hooks/plan-check.mjs:489`: give `git()` more than 5 s (for example 20 s, still under the 60 s hook timeout), or retry once on a timeout, so that a slow git is not read as "not a git work tree".

## suite_s

`verify.sh` sets `suite_s`, the whole seconds the test command ran (bash `SECONDS`, so within a second; no lock wait, listings or base run), right after the run. `log_gate` then adds it to every later record of that gate, in both modes. It covers a pass, a fail, a timeout (`tests_failed` with `timed_out`, `handback_timed_out`), the isolated warn, `max_blocks_reached`, the bugfix records after a run and `test_gate_error` after a run. The hand-back's store passes it to `test-gate-cache.mjs put` (12th argument) and keeps it as the entry's `suite_s`. `take` prints it as line 5, and the message now starts at line 6. A stop that reuses the outcome logs that run's value. No record gets the field when no suite ran: a lock-wait give-up, the skips, no test command. An entry stored before 2.1.0 has no `suite_s`. It is still taken, and the stop's record has no field. Tests: `src/test-gate-records.test.mjs`, the five `suite_s` cases plus the extended hand-back fail case.
