# Fix notes: plan check (G-7, G-12, G-15, G-6)

Slice fix-plan-check. Each fix has a regression test written first and seen failing. dist/ not rebuilt: `npm run build-plugin` is still due.

## G-7 (high): a retry of a slice that a later slice DEPENDS on

- Changed: `.claude/hooks/plan-check.mjs`, third attempt. One order graph, built by one pure function `planOrder(launches, slice, depends)` and read by both checks. It replays the scope's allowed launches in log order: each slice's edges are the DEPENDS of its latest launch (a retry replaces its earlier line, so an edge of a superseded launch orders nothing). On a retry, an entry naming a slice that already leads back to it, directly or through other slices, is dropped; a first launch's line, and a slice naming itself, are kept whole. It returns `prior` (the graph of the earlier launches), `graph` (with this launch applied), `cycle` (this launch's edges lead back to it), `unordered` (launched slices this launch is in no order with, either way, transitively) and `lost` (two other launched slices that `prior` orders and `graph` does not). The hook blocks `file_overlap` when this launch's FILES overlap a slice in `unordered` (message unchanged, "f (owned by x)"), then `file_overlap` when a `lost` pair shares a file (new message: "this DEPENDS line of slice s drops the only order between slices that share files: x and y (f)"), then `dependency_cycle` on `cycle`. Both still block every time; no loop guard was touched. Header comment updated. The hook cannot be imported (it runs on import), so `src/plan-check-overlap.test.mjs` lifts `planOrder` out of the source text and calls it in-process.
- Tests (`src/plan-check-overlap.test.mjs`): through the hook, the attempt-1 sequence `a, b(a), a(b), c(a)` and the attempt-2 sequence `a(b), a(none), b(a), c(a)` (plan a; b DEPENDS a; c DEPENDS a; all own f.txt): the last launch blocked with `file_overlap`, owned by b; the original G-7 retry of a after b(a), allowed with `DEPENDS: none` and `DEPENDS: b`; a cycle of first launches `x(y), y(x)` blocked with `dependency_cycle`; an overlap with no order blocked; a retry of s that drops the only order between x and y (x DEPENDS s, s DEPENDS y, x and y share f.txt, s owns g.txt) blocked, and the same retry keeping `DEPENDS: y` allowed. In-process: every sequence of up to four launches of a, b, c (all owning f.txt), each launch any slice with any DEPENDS over the other two: 22,620 decisions in about 80 ms. After each, the decision is blocked exactly when the launch closes a cycle or leaves two launched slices in no order; after an allowed launch every two launched slices are ordered and the graph equals the one the next decision rebuilds from the log; a retry is never blocked by a slice that depends on it, never a cycle, and its latest line plus any of its dependants is allowed. Seen failing before the fix: the attempt-2 sequence, the lost-order case and the walk (3 of the 6 new tests; the attempt-1 sequence was already fixed by attempt 2).
- Changed expectation in the attempt-2 test of this slice (not a base test): after `b(a)`, a retry `b` with `DEPENDS: none` is now blocked (`file_overlap`, owned by a), as the latest-line rule says and as the base (a853b8c) also blocked it.
- Against the base: a scratch differential over the same walk (histories the base allowed, every next launch) found no launch the base allowed that this rule blocks. New allowances: the G-7 retries, and a launch ordered against a sharing slice only transitively (`b DEPENDS: m`, `m DEPENDS: a`).
- Visible effect: a fresh retry of `a` after `b` (`DEPENDS: a`) launched is allowed (`ok`), with `DEPENDS: none` or `DEPENDS: b`. A real overlap (no order either way, also b and c after a retry of a, whatever the retry's line or an earlier launch's line said) and a cycle formed by first launches still block every time.
- Docs to update: `README.md:415` and `docs/native-mode.md:320` (the limitation stays true for a broken plan, but add that a retry of a planned slice is judged against the run's graph); `docs/native-mode.md:82` and `.claude/rules/agents.md` ("overlap another slice's files outside DEPENDS": now outside the run's DEPENDS order, transitive).
