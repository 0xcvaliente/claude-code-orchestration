# Harness research, 2026-11-10

This report covers what changed in Claude Code between 2.1.316, where [the last report](research-2026-10-31.md) stopped, and 2.1.322, and what the orchestration plugin should do about it. It became release 1.2.0.

Sources:
- the raw Claude Code changelog, 2.1.317 to 2.1.322;
- the current docs pages (hooks, subagents, workflows, plugins and mods, settings, tools, headless, prompt caching, status line, advisor, goal), read from local copies fetched that day;
- the claude-api reference bundled with Claude Code 2.1.322, for prices;
- this plugin's logs from 2026-11-01 to 2026-11-10;
- three live checks on 2.1.322 ([data/live-checks-2026-11-10.md](data/live-checks-2026-11-10.md)).

Every claim carries a tag, as in the last report: **verified** (probed live), **doc** (official docs or changelog), **data** (this repository's logs).

## Verdict

Nothing in 2.1.317 to 2.1.322 breaks the design, and `npm run check` passed on 2.1.322 before any change. The research found three gaps in the plugin itself, two of them in the gates, and four features worth taking.

**Gaps:**

1. **A researcher launched from a plain session could not search.** On macOS and Linux Claude Code leaves the Grep and Glob tools out of an agent whose tools also name Bash (**doc**, tools reference). The researcher lists both, and since 0.4.0 its guard held Bash to git, `wc`, `ls` and `du`. Three of five researchers in this research session failed on it (**verified**, Check C); the logs show 43 guard denials against 25 researchers (**data**).
2. **A turn-limit stop passed both gates.** A subagent that reaches `maxTurns` fires no SubagentStop (**verified**, Check A). The test gate and the journal run at SubagentStop, so a turn-limited implementer was never tested, counted as no attempt, and did not hold the review gate.
3. **The escalation rule knew only opus.** The Agent tool accepts `model: "fable"` and Fable 5.2 is the top tier since 2.1.321 (**doc**), but a review counted as the required senior review only when its model name contained `opus`.

**Features taken:** a report check before delivery, cost in the report, a subagent status line shipped by the plugin, and `onFailure: "block"` for the SDK pipeline's judge.

## What changed in Claude Code

Only what bears on this plugin; all **doc** unless tagged.

| Version | Change | Effect here |
|---|---|---|
| 2.1.321 | Fable 5.2 (`claude-fable-5-2`), the default Fable; the Agent tool's `model` accepts `fable` | The gates count opus or stronger (gap 3) |
| 2.1.319 | A plugin's `subagentStatusLine` command gets `${CLAUDE_PLUGIN_ROOT}` substituted | The plugin can ship a subagent status line |
| 2.1.319 | `permissions.denyInsteadOfPrompting`: a call that would prompt is denied and the turn goes on | Not taken: user or managed scope only, and headless runs already use `dontAsk` |
| 2.1.319 | PostToolUse hooks run, with up to 10 seconds, on tool calls that finish after an interrupt | The journal and the read log miss fewer calls; no change needed |
| 2.1.319 | After safeguards stop a subagent, Claude is told to retry narrower or tell the person, not to do the work itself | Matches the orchestrator's rule; no change |
| 2.1.318 | A background subagent's shell command moves to the background after 3 minutes | The implementer is told to wait for its result before reporting |
| 2.1.318 | Workflows no longer re-run finished agents when resumed after a usage limit | No change |
| 2.1.317 | `onFailure: "block"` for Agent SDK hook callbacks | The SDK pipeline's judge uses it |
| 2.1.317 | Subagents on a model other than the session's use that model's saved or default effort | No effect: every agent file sets its effort |
| 2.1.317 | The Read tool returns an unchanged file's content again instead of a stub | No change |
| 2.1.317 | `SendMessage` to a running background agent arrives earlier | No change |

Already there before 2.1.317, and used now:

- **`SubagentHandback`** (2.1.271). In auto mode a subagent delivers its report through this tool. A PreToolUse hook matched on it receives the report as `tool_input.message`, and a denied call is not delivered: the subagent is told, up to three times, to send it again (**doc**, hooks; **verified**, Check B).
- **A plugin's `settings.json`** takes effect for exactly two keys, `agent` and `subagentStatusLine` (**doc**, plugin components).
- **Grep and Glob absent by default** on macOS and Linux since 2.1.117, back for a subagent that lists them and leaves out Bash, or for a session that names them in `--allowedTools` (**doc**).

Unchanged: agent teams are still experimental and do not run under `claude -p`; the workflow script API is the one `orchestrate.js` uses (a research pass compared the script with the docs and the bundled authoring reference and found no call or option that is undocumented or documented differently).

## Cost

List prices per million tokens from the bundled claude-api reference, cached 2026-11-03 (**doc**):

| Model | Input | Output | Cache read |
|---|---|---|---|
| Fable 5.2 | $8 | $40 | $0.20 |
| Opus 5.5 | $4 | $20 | $0.20 |
| Sonnet 5.5 | $2 | $10 | $0.10 |
| Haiku 5.5 (prompts up to 100K) | $0.10 | $0.50 | $0.01 |

A cache write costs 1.25 times input at the five-minute lifetime and 2 times at the one-hour lifetime.

- **Opus is 2 times Sonnet on every token type**, so the same run costs twice as much.
- **Fable 5.2 and Opus 5.5 read the cache at the same price.** On the logged implementer mix, a run on Fable costs about 1.6 times the same run on Opus, not 2 times.
- **A correction.** The changelog entry for Sonnet 5.5 says cache reads cost $0.20; the bundled reference, which is newer, says $0.10. An early summary of this research used the changelog figure and concluded that Opus cost about 1.4 to 1.5 times Sonnet. With $0.10 it is 2 times. `scripts/prices.mjs` uses the reference.

## Reviews

Two independent reviews on opus read the finished changes with no view of how they were built.

- **Researcher guard.** The review failed the first version: it allowed commands that start a program or never end. `rg -e -- --pre=/bin/sh foo .` ran the program (the check stopped at a lone `--`, which ripgrep read as the pattern), `rg -z` starts decompression programs, `tail -5f` and GNU's `tail --fol` follow for ever, and `cat /dev/zero` never ends. All are refused now and each has a test; the option check reads every word, and `head` and `tail` take long options from an allowlist too.
- **Gates and hand-back hooks.** The review passed them with three gaps below the cutoff, all fixed: the quote check could refuse a hand-back with no agent id three times; a refusal whose log record failed to write could repeat; and `npm run check` failed once `npm run eval` had written its reports into `dist/plugin`.
- **Found while fixing.** An implementer the person stopped early would have blocked again after every later implementer stop. The `implementer_unfinished` loop guard is now per agent for the whole session.

## Checks after the build

- `npm run check`: typecheck, the tests, check-agents and check-plugin pass. The dashboard's 91 tests pass (`npm run test-dashboard`).
- **A researcher with the new list** answered three search questions in 4 tool calls and about 25k tokens, with nothing refused (Check C).
- **One bench pair**, `t2-single` at a 6-minute cap, 1 run each, so a smoke test and not a measurement: plain Sonnet scored 3 of 3 hidden tests in 18 s on about 120k tokens; the orchestrator with the 1.2.0 hooks scored 3 of 3 in 80 s on about 374k tokens. Its logs show the path the gates expect: a light-path implementer, `tests_passed`, a Sonnet review, the Opus review, `reviewer_passed`.
- **`npm run eval`**, bounded to `t2-single`, one run, plugin arm only, twice: it runs end to end in about a minute for about $0.37. 4 of 7 graders passed both times.

## Considered and not taken

- **The advisor.** The last report called it API-only. It works in Claude Code, including `claude -p` and subagents, which inherit the configured advisor (**doc**), and `scripts/orchestrate.sh` already passes `ORCH_ADVISOR`. It is experimental, needs the Anthropic API and reads the whole conversation uncached on every call. A Sonnet implementer with an Opus advisor is a candidate to replace the third attempt on Opus: bench it first.
- **A one-hour cache for workers.** Subagents get five minutes even on a subscription (**doc**). A retry resumes the implementer after a review that takes minutes, so its context may be written again. Agent frontmatter accepts `experimental.cacheTtl: 1h` and the setting `subagentPromptCacheTtl` does the same for every subagent, at twice the write price. Decide from `cache_rewrites` once it has data.
- **`autoCompactWindow` per agent.** Opus implementers average 47 turns and about 150k tokens of context per turn. Compaction would cut cost and may cost quality: an experiment.
- **Fable as a default tier.** Accepted wherever opus is required; no default raised without a benchmark.
- **Agent teams.** Still experimental, and not available under `claude -p`.
- **`/goal`.** Its evaluator is a small model that reads only the conversation; the Stop gate reads the logs.
- **The plugin `agent` setting.** It would make the orchestrator the main agent of every session with the plugin enabled.
- **Model-judged hooks** (`type: "prompt"`, `type: "agent"`) for the gates. The gates stay deterministic.
- **SubagentStart `additionalContext`** for the skill hints. The event carries no brief, so the plan check's rewrite stays.
- **Workflow `budget` and `stallMs`.** Documented and unused; no data yet says the workflow needs them.
- **The `claude -p` background wording.** The docs now describe a wait of up to 10 idle minutes for background work before it is stopped and its result dropped. The rule "never leave a background shell task running" stands and its wording, verified on 2.1.314, was not re-probed.

## Open

- A bench pair for the advisor and for the one-hour cache.
- The eval's three failing graders on `t2-single`. `orch-agent-used` expects an orchestration agent, and the case's own description says the plugin should stay light there, so in a one-arm run it counts against a correct route. `results-nonempty` and `results-pass` did not find a `pass` or `fail 0` line in the `test-results.txt` the session wrote, both times; the run's files are removed with its temporary folder, so the cause is not known (a coloured or differently formatted `npm test` output is one guess).
- `cache_rewrites` needs a week or two of runs before the cache lifetime is decided.
- The subagent status line has unit tests and no terminal check.
- CI still does not run or typecheck the dashboard.
