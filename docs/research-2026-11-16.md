## Test gate under load

Live use on the day showed a problem that no finding named ([Check 7](data/live-checks-2026-11-16.md#check-7-four-isolated-implementers-stopping-together)). Four isolated implementers stopped within two minutes. Their gates ran four whole suites at once, each took 554 to 590 s instead of about 120 s, and Claude Code ended one agent as stalled while its gate still ran.

The slice `fix-gate-load` changed `.claude/hooks/verify.sh` only ([fix notes](data/audit-2026-11-16/fix-notes-gate-load.md)):

1. **Budget under the stall limit.** Claude Code ends a subagent with no progress for `CLAUDE_ASYNC_AGENT_STALL_TIMEOUT_MS` (default 600000 ms), and time in a stop hook counts. The hook budget `ORCH_HOOK_BUDGET_S` now defaults to, and is capped at, min(870, stall limit in seconds - 60): 540 s with Claude Code's defaults. So the gate writes its record before the agent is ended.
2. **One suite at a time.** The gate takes `test-gate.lock` in the project's state dir before the test run and holds it through the base run or bugfix check. Gates of one project wait for each other; the wait counts against the budget.
3. **No silent skip.** When the time left falls to the floor (min(120 s, budget / 4, the test run's own limit)) while another gate holds the lock, an isolated gate logs `tests_failed_isolated` with `not_run: 1`. That is a doubt signal, so the slice needs a passing opus review. The shared tree runs its suite anyway, without the lock.

Regression tests: `src/test-gate-load.test.mjs`, eight tests.

## Limits the fixes leave

Each limit comes from the fix notes named.

### Run model and review gate

- On a Claude Code without `background_tasks` in the Stop input, an agent still fixing after a test-gate block can be gated before it stops again (`fix-run-model`, G-2).
- A carried slice that was final and passed, then fails a review in the new run, keeps the review gate allowing with `reviewer_passed`: it has no attempt in the new run. The plan check blocks an unplanned implementer of it with `not_in_plan` (`fix-run-pane` item 1).
- The pane cannot read test-gate records, so it shows neither `test_gate_gave_up` nor `tests_failed_isolated`. It keeps at most 500 records (`fix-run-pane`).
- The pane does not see the second stop of a hand-back (`continues` on the stop record), so it can count one review twice (`fix-run-pane`).

### Plan check

- A retry of a planned slice is judged against the run's DEPENDS order. For a plan that is itself broken, `file_overlap` and `dependency_cycle` still block every time (`fix-plan-check`, G-7).

### Test gate

- An isolated `warn` failure still pays for a base run (`fix-test-gate`, T-12 second half not done).
- `unittest.main(failfast=True)` inside a script cannot be seen. A unittest run cut short by a crash prints no test names and keeps the block (`fix-test-gate`, T-4).
- A cargo workspace member whose folder name differs from its package name does not match, so its bugfix slice still blocks (`fix-test-gate`, T-13).
- A gate killed with SIGKILL leaves its lock; the next gate takes it over as stale, and the killed gate's suite may still run then. A reused pid keeps a dead holder's lock until it is 900 s old (`fix-gate-load`).
- The takeover guard narrows one race but does not close it; it needs three gates within microseconds (`fix-gate-load`).
- The lock is per project. Suites of different projects still run at once (`fix-gate-load`).
- Waiting serialises: with many siblings, the last stops may reach the floor and get `not_run` (isolated) or run without the lock (shared tree) (`fix-gate-load`).
- The floor of 120 s is a guess for this repository; a slower suite still gets a timed-out run (`fix-gate-load`).
- A `KIND: bugfix` slice that waited long for the lock may get `bugfix_timeout` (`fix-gate-load`).

### Researcher guard

- A glob that the shell expands to a device (`cat /dev/zer?`) is not judged (`fix-guards`, T-5).
- A FIFO the shell reaches other than by the command's operands, and Linux `/proc/self/fd`, are not judged (`fix-guards-2` item 2, `fix-researcher-cd` item 3).
- A shell function or alias named `cd` is not seen (`fix-researcher-cd` item 2).

### Report check and quote check

- A quote-check refusal without a `tool_use_id`, finishing before `handback-check.mjs` writes its capture, is not tied to that capture (`fix-guards`, G-14).

### Native judge hook

- The hook sees Bash only: Write and Edit never reach it. These stay out of reach of the `judge-prompts` refusal: a glob (`judge-*`), a name built at run time, a `cd` into the parent then a relative glob, a spelling nested deeper than 4 script strings, and a top-level line the tokenizer cannot read, which gets the raw-text look only (`fix-judge-hook`, `fix-guards-2` item 1).
- After the update, a session started before it has no recorded request until the person types again (`fix-judge-hook`).

### Bash judge refusals that cost legitimate uses

From `fix-judge` and `fix-judge-2`; docs/bash-judge.md section 11 lists them with the way around each:

- `PS4='+ ' bash -x run.sh` (J-6).
- A here-document delimiter holding `$` or a backtick (J-5).
- A backtick inside a quoted subscript, as in a commit message `'use arr[`i`]'` (J-10); arithmetic with parentheses in a quoted subscript (J-10, second pass).
- `set -A` of a zsh table, `${aliases[p]:-a=b}`, `${:-functions=x}`, a reading expansion of a table followed by any `=`, and a table word behind a keyword or wrapper even in a search (J-9).
- A variable named `commands` (J-8).
- Reading an exec key with `git config --get` (J-4).
- A filter-branch filter that is refused as a command of its own (J-3).
- Still denied after J-15: `+=`, partial quoting, `--config-env` and `EDITOR=true`.

### Headless launch scripts

- The headless git allow and deny lists stop mistakes, not a command built to pass them: `git -C /r branch -D main status` passes. A commit message containing ` -c` is refused (`fix-scripts`, W-3).

### Skills

- A suggestion from goal words can still name a skill that does not fit the slice; the worker skips it (`fix-hooks-small`, W-10).
- Commit messages, author and committer identities and tags are not scanned. No tag is pushed (`fix-skill-gate`, `fix-guards-2` item 3).
- A draft branch that merges its base is blocked; rebase it instead (`fix-skill-gate`).
- The gate's range relies on `refs/remotes/origin/*` as fresh as the last fetch; the publish step is the one that compares with the push target (`fix-skill-gate`).

### Status line

- A terminal that draws ambiguous-width characters as two columns shows those rows wider than counted (`fix-hooks-small`, D-3).

### Gated workflow

- Retries of isolated slices after their merged review run one slice at a time, since each merge changes the shared tree (`fix-sdk-workflow`, W-2).

## Unproven leads
