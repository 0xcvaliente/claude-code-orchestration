# claude-code-orchestration

Two orchestrators for the same job (split a task, build slices in parallel, gate on tests, verify independently):

- SDK pipeline: `src/` (TypeScript on the Agent SDK). Code in a git repository only. Order is fixed in code. Worktree per slice, optional token cap (off by default), telemetry in `runs/`. Frozen since 0.3.0: maintenance only, no new features.
- Native: `.claude/` (agents, hooks, skill, workflow). Any task: code, research, writing, analysis or operations. Run with `claude --agent orchestrator`. Order is the orchestrator's prompt, plus hook gates (test gate, review gate, plan check and run journal). Git machinery (worktrees, checkpoint commits, the integrator) is for code in git: parallel slices run in worktrees there, code outside git runs one slice at a time, and work that changes no code may run slices with disjoint files in parallel in the shared folder. The test gate runs wherever there is a test command and skips only a prose-only change in a git work tree. The triage fact `code` changes one routing rule, the parallel-files threshold (`TRIAGE.minParallelFilesCode` 10, `minParallelFilesNonCode` 4; a missing `code` counts as code). It also decides whether git machinery is used and, in `npm run auto`, whether web tools are allowed. The test gate never reads it. The review gate covers every task. The gated workflow `.claude/workflows/orchestrate.js` (plugin: `/orchestration:orchestrate`, project copy: `/orchestrate`) fixes the order in code; only the person starts it.

## Commands
- `npm run check`: typecheck, tests, check-agents and check-plugin in one go; CI (`.github/workflows/ci.yml`) runs it on push and pull request to main. It must pass before finishing.
- `npm test` / `npm run typecheck`: the first two parts of that. `npm test` covers the judge (`src/judge.test.ts`, `src/agent.test.ts`, model faked). `npx tsx scripts/sandbox-smoke.mjs <scratch-dir>`: one real sandboxed `query()` (needs a logged-in `claude`).
- `npm run check-agents`: fails if `.claude/agents/*.md` drift from `src/config.ts`; `npm run sync-agents` fixes it.
- `npm run native -- "task" [repo]`: headless native run (needs a logged-in `claude`). `npm run auto -- "task" [repo]`: same, but triage picks plain, reviewed or the orchestrator first.
- `npm run report`: HTML timeline from `.claude/state/` (or the plugin's per-user state dir). `npm run build-plugin`: `dist/plugin` and `dist/dashboard` (committed; `npm run check-plugin` fails when either is stale). `dashboard/` is the source of the live orchestration pane (a Claude Code function-hooks mod; it opens on any typed prompt, registers the `route` tool, and signs a run off only once no agent runs and the main turn has ended; details in `docs/dashboard.md`): the build ships it inside the plugin, with its state owner renamed to `orchestration`, and alone as `dist/dashboard`. `statusline/statusline.sh` is the status line script (a plugin cannot set `statusLine`; `npm run install-statusline` copies it to `~/.claude/statusline.sh` and prints the setting; `src/statusline.test.ts` covers it, skipped without `jq`). `npm run orchestrate` runs `claude --agent orchestrator` with the dashboard loaded; `npm run test-dashboard` runs its test (needs the `claude` CLI). It reads `SLICE:`, `FILES:` and `DEPENDS:` from each agent brief, so keep those lines at the start of briefs (the orchestrator's rules already require them).
- `npm run eval`: `claude plugin eval` on `dist/plugin` with the four cases in `evals/` (from bench tasks t2, t1, c1, d1; free graders; plugin vs no-plugin). Paid, capped by `--max-cost-usd 10`; not smoke-run yet. Bounded: `npm run eval -- --case t2-single --runs 1 --ablation none --max-cost-usd 2`.
- `npm run bench -- --matrix bench/matrix/<name>.json` runs the benchmark (see bench/README.md); `npm run bench:validate` checks every task's graders with no model calls.

## Rules
- `src/config.ts` is the source of truth for model, effort, maxTurns and the triage thresholds (`TRIAGE`). After editing it, run `npm run sync-agents`.
- Pushes and deletes. Native path (unchanged): `scripts/orchestrate.sh` passes `UNSAFE_BASH` to every headless run as `--disallowedTools`, the agents are told not to push, and project settings deny `git remote`, `sudo` and `rm -rf` (remove specific paths with `rm -r <path>`) but not `git push`: an interactive session may push as its permission mode allows. SDK workers (`solo`, `writer`, `verifier`) use the Bash judge (`src/judge.ts`, wired in `src/agent.ts`; details in `docs/bash-judge.md`): `sudo` is denied by rule; `git push`/`git remote` and a plain recursive `rm` run only when an opus judge approves, with the user's original task passed on this invocation as the authority (a resume without `--task` refuses them); `rm -rf` of catastrophic targets and any form the tokenizer cannot read are always denied; every failure is a deny. `ORCH_JUDGE=off` restores the old denial (`UNSAFE_BASH`). Best-effort, not a sandbox. Native sessions: `ORCH_JUDGE=native` opts in to the deny-only judge hook (`judge-hook.mjs` plus `prompt-capture.mjs`, project and plugin; `ORCH_JUDGE_TIMEOUT_MS` capped at 45000); see `docs/bash-judge.md`, "Native hook".
- Seven agents are blocked: Claude Code's six built-in subagents (`general-purpose`, `claude`, `Explore`, `Plan`, `claude-code-guide`, `statusline-setup`) and `fork`. `DENIED_AGENTS` in `src/config.ts` is in `permissions.deny` (`policy.test.ts` keeps them in step), and `scripts/orchestrate.sh` exports `CLAUDE_AGENT_SDK_DISABLE_BUILTIN_AGENTS=1` and `CLAUDE_CODE_FORK_SUBAGENT=0` for headless runs. The implementer has `disallowedTools: Agent`. Only this repo's researcher, implementer, reviewer and integrator remain. The benchmark's plain runs in README "Why a router" predate this and self-delegated to `general-purpose`; the campaign run with the built-ins blocked is in `docs/benchmark-builtins-blocked.md`.
- Brief and reply lines have one parser, `.claude/hooks/brief.mjs` (spec: `docs/brief-grammar.md`). `.claude/hooks/run.mjs` loads the log records and folds them into runs for the gates. Gate settings: `ORCH_ESCALATION` (`off` or `always`), `ORCH_ALLOW_BUILTINS=1` and `ORCH_RUN_STALE_MIN` (default 30); see README "Gates, runs and briefs".
- Agent-file, hook and settings rules live in `.claude/rules/agents.md` and load when you touch those files.
- When testing hook scripts in zsh, pass JSON with `printf '%s'`, not `echo` (zsh expands `\n`).
