# claude-code-orchestration

Two orchestrators for the same job (split a task, build slices in parallel, gate on tests, verify independently):

- SDK pipeline: `src/` (TypeScript on the Agent SDK). Code in a git repository only. Order is fixed in code. Worktree per slice, optional token cap (off by default), telemetry in `runs/`. Frozen since 0.3.0: maintenance only, no new features.
- Native: `.claude/` (agents, hooks, skill, workflow). Any task: code, research, writing, analysis or operations. Run with `claude --agent orchestrator`. Order is the orchestrator's prompt, plus hook gates (test gate, review gate, plan check and run journal). Git machinery (worktrees, checkpoint commits, the integrator) is for code in git: parallel slices run in worktrees there, code outside git runs one slice at a time, and work that changes no code may run slices with disjoint files in parallel in the shared folder. The test gate runs wherever there is a test command and skips only a prose-only change in a git work tree. The triage fact `code` changes one routing rule, the parallel-files threshold (`TRIAGE.minParallelFilesCode` 10, `minParallelFilesNonCode` 4; a missing `code` counts as code). It also decides whether git machinery is used and, in `npm run auto`, whether web tools are allowed. The test gate never reads it. The review gate covers every task. The gated workflow `.claude/workflows/orchestrate.js` (plugin: `/orchestration:orchestrate`, project copy: `/orchestrate`) fixes the order in code; only the person starts it.

## Commands
- `npm run check`: typecheck, tests, check-agents and check-plugin in one go; CI (`.github/workflows/ci.yml`) runs it on push and pull request to main. It must pass before finishing.
- `npm test` / `npm run typecheck`: the first two parts of that. `npm test` covers the judge (`src/judge.test.ts`, `src/agent.test.ts`, model faked). `npx tsx scripts/sandbox-smoke.mjs <scratch-dir>`: one real sandboxed `query()` (needs a logged-in `claude`).
- `npm run check-agents`: fails if `.claude/agents/*.md` drift from `src/config.ts`; `npm run sync-agents` fixes it.
- `npm run native -- "task" [repo]`: headless native run (needs a logged-in `claude`). `npm run auto -- "task" [repo]`: same, but triage picks plain, reviewed or the orchestrator first. `ORCH_SESSION_PERSISTENCE=1` makes `scripts/orchestrate.sh` (and so both) keep session and subagent transcripts (default `--no-session-persistence`), so telemetry records per-agent tokens in headless runs; the `reader-*` bench arms set it.
- `npm run report`: HTML timeline from `.claude/state/` (or the plugin's per-user state dir), with an estimated cost by role and model at the list prices in `scripts/prices.mjs`. `npm run build-plugin`: `dist/plugin` and `dist/dashboard` (committed; `npm run check-plugin` fails when either is stale). `dashboard/` is the source of the live orchestration pane (a Claude Code function-hooks mod; it opens on any typed prompt, registers the `route` tool, and signs a run off only once no agent runs and the main turn has ended; details in `docs/dashboard.md`): the build ships it inside the plugin, with its state owner renamed to `orchestration`, and alone as `dist/dashboard`. `statusline/statusline.sh` is the status line script (a plugin cannot set `statusLine`; `npm run install-statusline` copies it to `~/.claude/statusline.sh` and prints the setting; `src/statusline.test.ts` covers it, skipped without `jq`). A plugin can set `subagentStatusLine`, so the build ships `.claude/hooks/subagent-statusline.mjs` as the plugin's `settings.json`: the row of each worker under the prompt shows its slice, attempt, model and tokens. `npm run orchestrate` runs `claude --agent orchestrator` with the dashboard loaded; `npm run test-dashboard` runs its test (needs the `claude` CLI). It reads `SLICE:`, `FILES:` and `DEPENDS:` from each agent brief, so keep those lines at the start of briefs (the orchestrator's rules already require them).
- `npm run eval`: `claude plugin eval` on `dist/plugin` with the four cases in `evals/` (from bench tasks t2, t1, c1, d1; free graders; plugin vs no-plugin). Paid, capped by `--max-cost-usd 10`. Smoke-run on 2026-11-10 (the bounded command below, twice, about $0.37 each): it runs end to end; 4 of 7 graders pass, and the three that fail are not understood yet (`docs/research-2026-11-10.md`, Open). Bounded: `npm run eval -- --case t2-single --runs 1 --ablation none --max-cost-usd 2`.
- `npm run bench -- --matrix bench/matrix/<name>.json` runs the benchmark (see bench/README.md); `npm run bench:validate` checks every task's graders with no model calls.

## Rules
- `src/config.ts` is the source of truth for model, effort, maxTurns and the triage thresholds (`TRIAGE`). After editing it, run `npm run sync-agents`.
- Pushes and deletes. Native path (unchanged): `scripts/orchestrate.sh` passes `UNSAFE_BASH` to every headless run as `--disallowedTools`, the agents are told not to push, and project settings deny `git remote`, `sudo` and `rm -rf` (remove specific paths with `rm -r <path>`) but not `git push`: an interactive session may push as its permission mode allows. SDK workers (`solo`, `writer`, `verifier`) use the Bash judge (`src/judge.ts`, wired in `src/agent.ts`; details in `docs/bash-judge.md`): `sudo` is denied by rule; `git push`/`git remote` and a plain recursive `rm` run only when an opus judge approves, with the user's original task passed on this invocation as the authority (a resume without `--task` refuses them); `rm -rf` of catastrophic targets and any form the tokenizer cannot read are always denied; every failure is a deny. `ORCH_JUDGE=off` restores the old denial (`UNSAFE_BASH`). Best-effort, not a sandbox. Native sessions: `ORCH_JUDGE=native` opts in to the deny-only judge hook (`judge-hook.mjs` plus `prompt-capture.mjs`, project and plugin; `ORCH_JUDGE_TIMEOUT_MS` capped at 45000); see `docs/bash-judge.md`, "Native hook".
- Seven agents are blocked: Claude Code's six built-in subagents (`general-purpose`, `claude`, `Explore`, `Plan`, `claude-code-guide`, `statusline-setup`) and `fork`. `DENIED_AGENTS` in `src/config.ts` is in `permissions.deny` (`policy.test.ts` keeps them in step), and `scripts/orchestrate.sh` exports `CLAUDE_AGENT_SDK_DISABLE_BUILTIN_AGENTS=1` and `CLAUDE_CODE_FORK_SUBAGENT=0` for headless runs. The implementer has `disallowedTools: Agent`. Only this repo's researcher, implementer, reviewer and integrator remain. The benchmark's plain runs in README "Why a router" predate this and self-delegated to `general-purpose`; the campaign run with the built-ins blocked is in `docs/benchmark-builtins-blocked.md`.
- Brief and reply lines have one parser, `.claude/hooks/brief.mjs` (spec: `docs/brief-grammar.md`). `.claude/hooks/run.mjs` loads the log records and folds them into runs for the gates. Gate settings: `ORCH_ESCALATION` (`off` or `always`), `ORCH_ALLOW_BUILTINS=1` and `ORCH_RUN_STALE_MIN` (default 30); see README "The gates" and "Briefs and replies". A slice is final only when it failed for good or its latest pass meets the escalation rule (no doubt signal, or an opus pass after its latest attempt), so a sonnet pass awaiting its opus review keeps the run open (`docs/brief-grammar.md`, "Final slice").
- 0.4.0 lines and gates. Briefs may carry `SOURCES:`/`READ:` (researchers), `KIND: bugfix` (implementers: failing reproduction test first) and `VALIDATE: gaps` (a reviewer re-checks another review's gaps before a retry); replies may carry `GAP: <0-100> <text>` (reviewers) and `QUOTE: <locator> | <verbatim text>` (researchers). New hooks: `read-log.mjs`, `researcher-guard.mjs`, `egress-guard.mjs`, `compact-context.mjs`, `quote-check.mjs`, and the read router in `plan-check.mjs` (profiles files with `file-profile.mjs`; `plan-check.mjs` is the only hook that ever returns an allow). The stall gate (`replan_required`) is native-only. Switches: `ORCH_GAP_MIN` (default 80), `ORCH_STALL_GATE`, `ORCH_GUARDS`, `ORCH_READ_ROUTER` (opt-in), `ORCH_QUOTE_CHECK`, `ORCH_BASELINE` (test baseline: `inform` by default, failing tests still block and the message marks failures that also fail on the base as probably pre-existing; `allow`, opt-in and heuristic, allows when every qualified failure also fails on the base; `off`), `ORCH_BUGFIX_CHECK`; each also reads the plugin's `userConfig` value (`CLAUDE_PLUGIN_OPTION_<KEY>`), the environment winning. Name switches only in maintainer text, never in agent bodies, skills or the nudge's context. Run implementer and reviewer Bash in Claude Code's sandbox with a network allowlist: the guards are not a boundary. Details in `.claude/rules/agents.md`.
- 1.2.0 (Claude Code 2.1.317 to 2.1.322; research in `docs/research-2026-11-10.md`, probes in `docs/data/live-checks-2026-11-10.md`). The researcher's Bash list includes read-only search and paging (`grep`, `rg`, `find`, `head`, `tail`, `cat`), held to forms that cannot write or run anything by `researcher-guard.mjs`: on macOS and Linux an agent whose tools name Bash gets no Grep or Glob tool. The review gate blocks with `implementer_unfinished` when an implementer started and never stopped (a turn-limit stop fires no SubagentStop, so the test gate and the journal never saw it). A review on opus or a stronger model (`fable`) meets `opus_review_required`; defaults stay on opus. New hook `handback-check.mjs` (PreToolUse on `SubagentHandback`, auto mode): sends a worker's report back once when it has no STATUS line or a reviewer's pass leaves a checked id unanswered, and `quote-check.mjs` runs there too, before delivery. Switch: `ORCH_HANDBACK_CHECK=off` (userConfig `handback_check`, the 16th setting). Telemetry records `tokens.cache_write_1h` and `cache_rewrites`. The SDK pipeline is on Agent SDK 0.3.322 with `onFailure: "block"` on the judge's hook. Details in `.claude/rules/agents.md`.
- Skill selection (0.4.0 addendum). Implementer, researcher and reviewer briefs (never the integrator's) may carry `SKILLS: <comma-separated skill names>`, written by the orchestrator when a slice clearly needs an installed skill, named as the Skill tool lists it; workers load each with the Skill tool before starting and ignore one that does not fit (saying so in one line of the report, not under OPEN: a non-empty OPEN is a doubt signal). `plan-check.mjs` also appends a suggestion block to those launches: at most 3 installed skills (1 for reviewers), names and reason codes only, picked from FILES/SOURCES file types, the role and the goal's words, out of the skills found on disk (`~/.claude/skills`, with `synced/<uuid>/<name>` named `anthropic-skills:<name>`; the project's `.claude/skills`; enabled plugins' skills). Explicit SKILLS names not found on disk pass through, marked. Workflow agents get no hints (they never reach the plan check). Switch: `ORCH_SKILL_HINTS=off` (userConfig `skill_hints`). Researcher and reviewer have the `Skill` tool, the integrator does not. The plan check's allow widens: it may return `updatedInput` with allow for this plugin's implementer (only when its rules allow with `ok` or `light_path`), researcher and reviewer, combining the read router's model change and the hint text in one `updatedInput`; never for built-ins or fork, never lowering a model.
- Agent-file, hook and settings rules live in `.claude/rules/agents.md` and load when you touch those files.
- When testing hook scripts in zsh, pass JSON with `printf '%s'`, not `echo` (zsh expands `\n`).
